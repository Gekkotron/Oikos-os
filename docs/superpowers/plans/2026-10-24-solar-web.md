# Solar forecast web card and page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the hub's Solcast forecast in the web UI: a solar card beside the weather card in the overview header (measured production against the forecast) and a `/solar` page opened from it.

**Architecture:** Pure presentation in a new `crates/oikos-web/src/solar/` module (figures, curve geometry, measured-production sources), unit-tested natively. `House` gains a `solar` signal fed by `GET /api/v1/solar` and `WsEvent::SolarChanged`, like weather. One app-wide loader keeps today's measured kWh and the measured 30-minute curve fresh; the header card and the page read it from context. The page is built like `screens/weather.rs`.

**Tech Stack:** Rust 2024, Leptos (CSR wasm), leptos_router, `chrono`/`chrono-tz`, inline SVG, plain CSS in `crates/oikos-web/styles/main.css`, `wasm-pack test --headless --chrome` for DOM tests.

**Spec:** `docs/superpowers/specs/2026-10-23-solcast-solar-forecast-design.md` §8–§9 (Plan 2). Plan 1 (crate + hub) is merged; `SolarView` lives in `crates/oikos-api/src/solar.rs`.

## Global Constraints

- No hard-coded French or English strings outside `crates/oikos-web/src/i18n.rs`; every new text has an EN and a FR value.
- Theme tokens only (`var(--…)` from `styles/tokens.css`), so Ivoire and Night Glass both work; sun icon is `icons::SUN`.
- Numbers in the UI language via `i18n::home_number` (comma decimals in FR); kWh one decimal, kW one decimal; times via `i18n::home_time`.
- The header's right column never grows taller than the left column (date → chips) on desktop.
- The card is hidden when there is no `SolarView` or `fetched_at` is older than 24 h (86 400 s); the weather card then renders exactly as today (single-card layout).
- Generic project: no machine, address, site id or room name in tracked files or fixtures.
- Measured production = entities whose override `energyRole` is `solar` (groups excluded, as `oikos_api::energy_entities` does), honouring `energyInvert`; several are summed.
- Before any build: `du -sh ~/dev-scratch/cargo-target`; over 5 GB run `cargo clean`. Check `df -h ~` and run per-crate tests when under 5 GB free.
- Commits as `Gekkotron`: `git -c user.name=Gekkotron -c user.email=60887050+Gekkotron@users.noreply.github.com commit …`, message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions made while planning (spec left them open or the code changed the picture)

- **Measured today reuses the Energy page's counters.** `screens/energy.rs` already keeps an app-wide `KwhToday` map (counter id → kWh since midnight, refreshed every 5 min). When the solar entities have counters (an energy-unit solar entity, or the counter `EnergyMeters::meter_for` pairs with a power one), measured today = the sum of those counters from `KwhToday`, so the card agrees with the Energy page. Only when no counter exists does the loader call `/history/today?kind=power` per power entity (spec §8.2).
- **Measured curve** comes from power-unit solar entities only (`/history/series?range=24h`, today's points, resampled to the forecast's period grid). No power entity → no measured curve → forecast fill (§8.3).
- **Series point time** `t` is read as the start of its window; a point belongs to the period `[end − minutes·60, end)`.
- **Yesterday / month / accuracy** read `/history/daily?days=30` once when the page mounts (counters with `kind=counter`, otherwise power entities with `kind=power`). `days[i].0` is converted to a house-local date.
- **Morning forecast rule (§7):** a `history.forecasts` row counts for accuracy only when `made_at ≤ sunrise(date) + 3600`; otherwise the Yesterday tile says "forecast at HH:MM".
- **Gap tile** = (measured so far − forecast so far) / forecast so far, signed, whole percent; hidden when forecast so far < 0.1 kWh or nothing is measured.
- **Sun tile** hidden when the sun times are the Paris fallback (`sun_today(..).3 == true`).

## Review Focus

1. **Solar entity offline or not recorded** (404 `not_recorded`, 503 history off): card falls back to the forecast fill with "≈" in the title, never shows `0,0` as measured. → Task 1 `measured_today_none_when_a_counter_is_missing`, Task 3 wasm `card_without_measured_shows_forecast_fill`.
2. **Inverted solar sensor** (`energyInvert`, negative watts): measured curve and kWh are positive, never a downward area. → Task 1 `inverted_power_source_is_positive`.
3. **Night / after the last producing period:** no "now" line, the whole measured area stays, tomorrow on the bottom line. → Task 2 `no_now_line_after_last_producing_period`.
4. **DST day (46 or 50 periods) and a `periods` list that starts mid-day after a restart:** day bounds come from the house zone, not 48 × 30 min. → Task 1 `day_bounds_on_dst_change`.
5. **Late replies:** a slow history reply from a previous refresh must not overwrite a newer one (the grid-day card had exactly this bug, fixed in 57c6fa1). → Task 4 generation counter, test `stale_generation_is_dropped`.

A failed fetch for a source leaves that source out (curve) or makes `today_kwh` `None` (kWh), never an error toast.
